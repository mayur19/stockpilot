# Quality attributes

Measurable targets for StockPilot and how each one is verified. "Implemented" verification runs today in `npm test` / CI (`.github/workflows/ci.yml`); "Planned" verification is tracked by the ticket shown and is not yet automated. Targets refer to the reference host in `docs/operations/deployment.md` (4 vCPU, 8 GB RAM, SSD, PostgreSQL on the same host) unless stated otherwise.

## 1. Correctness invariants (highest priority)

A warehouse system that is fast but oversells is worthless, so correctness targets are absolute and are checked both in pure code and in the database.

| ----- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |

## 2. Performance

### 2.1 Latency (server-side, measured from Fastify `onRequest` to `onSend`, warm pool)

| Endpoint class               | Examples                                                                           | p95 target               | p99 target    | Basis                                                                              | Verified by                                     |
| ---------------------------- | ---------------------------------------------------------------------------------- | ------------------------ | ------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------- |
| Liveness / readiness         | `GET /health`, `GET /ready`                                                        | 5 ms / 20 ms             | 20 ms / 50 ms | no I/O / one `count(*)`                                                            | Planned: SP-181 load scripts                    |
| Session-only reads           | `GET /auth/me`                                                                     | 20 ms                    | 50 ms         | one indexed join + throttled touch                                                 | Planned: SP-181                                 |
| Catalogue and topology reads | `GET /warehouses`, `GET /skus`, `GET /warehouses/:id/bins`                         | 50 ms                    | 120 ms        | indexed, `LIMIT 200`                                                               | Planned: SP-181                                 |
| Stock queries                | `GET /inventory/balances` (limit <= 200), `GET /inventory/movements` (keyset page) | 100 ms                   | 250 ms        | `stock_balances_lookup_idx`, `inventory_movements_org_wh_idx`                      | Planned: SP-181                                 |
| Ledger mutations             | `POST /inventory/receipts`, `/moves`, `/adjustments`                               | 150 ms                   | 300 ms        | 1–2 row locks, 3–5 statements in one transaction                                   | Planned: SP-181                                 |
| Allocation                   | `POST /allocations` with <= 20 lines and <= 500 candidate rows                     | 250 ms                   | 600 ms        | one locking `SELECT`, O(n log n) planning, one insert + one ledger append per pick | Planned: SP-181                                 |
| Release                      | `POST /allocations/:id/release`                                                    | 200 ms                   | 500 ms        | one `DEALLOCATE` per pick                                                          | Planned: SP-181                                 |
| Login                        | `POST /auth/login`                                                                 | 250 ms                   | 400 ms        | dominated by scrypt N=2^15 (deliberately slow, ~50–100 ms per hash)                | Planned: SP-181                                 |
| Projection verification      | `GET /inventory/projection/verify`                                                 | <= 5 s per 1 M movements | —             | full O(m) fold in memory; an admin operation, not interactive                      | Planned: SP-181; bounded by snapshots in SP-044 |

Interim verification: the database test suites run each endpoint against real PostgreSQL in CI within `testTimeout: 20_000`, which catches gross regressions but is not a latency gate.
